A failed package-registry migration truncated the authoritative registry index at `/app/data/registry_index.json`, and the control-plane resolver at `/app/workflow/resolver.py` evaluates stale draft rules rather than the registry governance board's final decisions. Two files survive beside the truncated index under `/app/data`: a pre-migration snapshot and a replay journal of the releases that arrived after it. The end state is that `/app/data/registry_index.json` holds the authoritative index those two determine between them, where how they merge, which wins where they overlap and what order the result carries are governance decisions rather than open questions; nothing the resolver reports means anything against any other index.

`/app/workflow/resolver.py` is a program whose behaviour matches the board's final decisions. It carries `--input` and `--output-dir` with the defaults it already documents; the registry index and the resolution policy always come from their fixed absolute paths under `/app/data`, and `--input` selects the request set alone. A run reads that index rather than rebuilding it. `/app/docs/report_spec.json` is the output contract: paths, schemas, required-field lists, field coercions, container shapes and sort orders. It says nothing about how any value is derived; that is settled in `/app/incident/registry_governance_log.md`, which is mostly routine noise and records rules drafted, revised and reversed over several months, and where its entries conflict the later dated decision governs.

A run is correct when all of this holds of it. It finishes inside the 120-second wall-clock budget the contract states. `/app/output/summary.json`, `/app/output/resolution.json` and `/app/output/install_plan.jsonl` are the only files in the directory it wrote into afterwards, whatever that directory held before it started -- an artifact from an earlier run, a scratch file, a subdirectory -- while the directory itself is still the one it was given, since the run does not own the path it writes into. Every value is derived from the operational inputs, with no packaging or semver library and no dynamically generated and executed code anywhere in it. The same request set yields the same three artifacts on every run, and an alternate request set yields that set's own answer. `/app/data/registry_snapshot_pre_migration.json`, `/app/data/registry_replay_journal.json` and `/app/docs/report_spec.json` are read rather than written and come back byte for byte unchanged, as does the frozen `/app/workflow/.resolver.original`.
